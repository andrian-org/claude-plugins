# The DGF version question offered the knowledge stamp 1.1.11 as its answer

**Date:** 2026-10-05 14:10
**Files:** skills/dgf/SKILL.md, skills/dgf-scaffold/SKILL.md, docs/pipeline.md, tests/test_skill_contracts.py
**Severity:** medium

## Problem

`/dgf` Step 3, Call 1, question 2 listed "the stamp's version, `unknown`, and a typed `X.Y.Z`"
as its options. The stamp is `1.1.11`, so the first and only concrete option was `1.1.11`. That
pushed every estate towards 1.1.11, although DGF has released up to 1.1.16. `/dgf-scaffold`'s
`dgf_version` question had no candidates at all, so the model built its options from what it
had read: the stamp again (`knowledge/application-layout.md` §6 names `1.1.11` as the props
file's only version). Either way, the user did not get to pick a version from a list of real
releases.

## Root Cause

The skill treated two different values as one: the release the shipped facts were **read at**
(the knowledge stamp) and the release the estate **runs** (the user's declaration). ADR 0019 says
only to *show* the stamp beside the question. The skill made it an option, and AskUserQuestion
puts the first option forward as the default. The release list that would let the user select
was already available through the DGF docs MCP (`list_release_notes`), but neither skill was
allowed to call it.

## Solution

Both skills now call `list_release_notes` before they ask, and offer the newest `X.Y.Z` releases
(three plus `unknown` in `/dgf`, four in `/dgf-scaffold`, newest first). They skip `NOTES-NEXT`
and `README`, and preselect nothing. Any other release is typed under Other. The stamp appears
only in `/dgf`'s question text, labelled as the release the facts were read at. When the MCP is
unavailable, `/dgf` offers only `unknown` and `/dgf-scaffold` asks for a typed version. Both
skills' `allowed-tools` gained `list_release_notes`, and `docs/pipeline.md` describes the
selection. No ADR changed: the fix brings the skill back to what ADR 0019 already decided.

## Prevention

- A value the user declares is never offered from a value the plugin holds for another reason.
  Name what each value means before you make it an option.
- When a source of truth for the choices exists (here, the MCP's release list), offer the options
  from it, and add its tool to `allowed-tools`.
- The first option of an AskUserQuestion reads as the default. A question with no default lists
  its options in a neutral order (newest first) and never marks one recommended.
- Regression check: `python3 -m unittest tests.test_skill_contracts` — `DgfVersionQuestion`
  holds both skills to the release list, no default, and no stamp offered as an option.
