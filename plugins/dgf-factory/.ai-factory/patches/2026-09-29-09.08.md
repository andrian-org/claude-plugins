# A comparison the script already made was handed to the model, and the exit stayed the script's

**Date:** 2026-09-29 09:08
**Files:** scripts/check_change.py, scripts/lib/baseline.py, scripts/lib/report.py, scripts/audit_root.py, skills/dgf-process/SKILL.md, skills/dgf-model/SKILL.md, skills/dgf-component/SKILL.md, docs/adr/0025-saved-baseline-without-git.md, docs/adr/README.md, docs/pipeline.md, docs/skill-authoring.md, AGENTS.md, .ai-factory/DESCRIPTION.md, .ai-factory/plans/feature-dgf-specific-skills.md, tests/test_check_change.py, tests/test_baseline.py, tests/test_audit_root.py, tests/test_skill_contracts.py, tests/test_report.py, tests/fixtures/known-bad/change-baseline-unusable/
**Severity:** high

## Problem

The eighth `/aif-verify` walked the seventh round's fix and found it incomplete in two ways.

- **An old malformed file masked a new break, without git.**
  - `/dgf-process` modify and `/dgf-model` add/modify took a baseline run before the write. After the
    write, the model was told to treat a line with the same code, file and message as pre-existing.
  - The script's exit was still computed with every finding new. So one old `FAMILY_UNRESOLVED`
    anywhere in the root (an exit-`3` code) made every run after the write exit `3`.
  - The exit-3 row gave no action for the other lines. A renamed state that broke an untouched
    workflow (`CHANGE_STATE_STATE_UNDECLARED`), or a removed field that unbound a form
    (`MODEL_CELL_UNBOUND`), never reached the exit-1 STOP.
  - The comparison itself broke `rules/base.md:147`: "Anything a script can decide must never be left
    to the model".
- **A misspelt root in a written file was stopped on.** Every template starts with `<?xml …?>`, and a
  declared file whose root no XSD reads exits 3 with `SCHEMA_UNSELECTABLE`, not `FAMILY_UNRESOLVED`.
  The confirm rows STOPped on it and left the broken file on disk. The baseline rows and the inspect
  rows did the same.
- **Smaller issues.**
  - The new contract tests passed three mutants.
  - `NOT AUDITED:` blamed `--app` when none was given.
  - `pipeline.md` claimed the change was never blamed for an old defect.
  - A process `/dgf-process` authored was confirmed on the new file alone, missing workflows already
    aimed at it.

## Root Cause

- **The fix reimplemented, in prose, a function the script already had.** `lib/baseline.py`'s
  `compare()` is exactly the "same code, file and message" rule. The seventh round reached for the
  skill because ADR 0018 §5 says a no-git run has no baseline. It did not ask whether the script could
  be given one.
- **Splitting the decision split it wrong.** With the comparison in the model and the exit code in the
  script, the two disagreed. The exit said "3", the comparison said "nothing new", and no row covered
  that pair.
- **An exit-3 code was routed by one example, not by the codes the call can emit.** The seventh round
  walked files with no XML declaration. The templates always carry one, and a declared file takes the
  other branch of `family.detect` (`SCHEMA_UNSELECTABLE`, not `FAMILY_UNRESOLVED`).
- **The contract tests were written to pass on the text, not to fail on its breakage.**
  - They checked only the rows right after a validator call.
  - They matched "correct it" as a substring.
  - They took any `--changed` call as a baseline.

## Solution

- **ADR 0025, by the user's decision.** `check_change.py` saves a baseline without git, and the gate
  never takes one, so ADR 0018 stands.
- **`--save-baseline FILE`** (with `--changed` only) runs the validators and writes their non-INFO
  findings, keyed by `baseline.key` with the root removed, with the root and the `--files` scope. It
  judges none of them, so its exit is the change checks'.
- **`--baseline FILE`** loads them as Findings and settles the run through the unchanged
  `baseline.compare()`, with no root forms. Its output is the same `PRE_EXISTING`/`FIXED` lines and
  the same exit rule as with a merge-base.
- **`BASELINE_UNUSABLE`** (exit 3) is a baseline that is missing, malformed, or saved for another
  root or `--files` scope, or that holds an unknown code or a bad row. A refused baseline never falls
  back to "every finding new". Either flag with `--base` or `--skip-validators` is a usage error.
- **The skills.**
  - `/dgf-process` (author and modify) and `/dgf-model` (add and modify) pass `--save-baseline` and
    then `--baseline` without git, with the file at `<root>/.dgf-factory/baseline.json`.
  - `/dgf-process` confirms an author over the whole root too.
  - Every exit-3 row after a write sends `FAMILY_UNRESOLVED`, or `SCHEMA_UNSELECTABLE` naming its root,
    back for correction; a dialect message stays a STOP.
  - The inspect and validate rows relay both codes as the file's defect.
- **`audit_root.reach_one`** prints `NOT AUDITED:` only under `--app`. Otherwise it prints
  `NONE: <ws> — no application … under the root now`.
- **Tests.**
  - 9 `SavedBaseline` tests in `test_check_change.py`, 8 of them failing before the fix. One passed
    early only because argparse already exits 3 on an unknown flag.
  - A known-bad case, `change-baseline-unusable`.
  - 5 direct `save`/`load` tests in `test_baseline.py`. A mutant that saves the raw message fails them.
  - `WritingSkills` rewritten: every exit-3 row after a write, and the exact save and compare pair.
    Four mutants now fail it.
  - An audit test for `NOT AUDITED:` without `--app`.
  - 889 tests pass with the dependencies, and without them (270 skipped).

## Prevention

- **Before writing a rule into a skill, ask whether a script already computes it.** If it does, pass
  the script what it needs: here, a saved run in place of the missing tree. Never restate the rule for
  the model.
- **Never let the model and a script share one decision.** If the script computes the exit, it must
  also compute everything the exit depends on. Otherwise a row meets a combination no one wrote.
- **Route an exit code from the full list of codes that call can emit**, not from the case that was
  walked. For each validator, list its exit-3 codes and messages, and ask which are about the file,
  which about the call, and which about the plugin.
- **A test of a prose rule must fail when the rule is broken.**
  - Match the exact clause, not a word that also appears in its negation.
  - Assert the command pair, not a nearby line.
  - Run each mutant once before trusting the test.
- **Walk the fixed path in a root that holds every kind of old defect**: an old error, an old warning
  and an old exit-3 file together. A fix for "old defects" that is walked with one kind proves only
  that kind.
