# An entity that cannot load passed clean, a probe stood in for the template, and the audit misread its own failures

**Date:** 2026-09-27 22:48
**Files:** scripts/lib/model.py, scripts/validate_model.py, scripts/lib/report.py, scripts/audit_root.py, scripts/lib/edges.py, knowledge/data-model.md, knowledge/reference-graph.md, provenance/knowledge/data-model.md, docs/adr/0023-dgf-specific-skills.md, docs/pipeline.md, docs/architecture.md, docs/getting-started.md, AGENTS.md, skills/dgf-model/SKILL.md, skills/dgf-component/SKILL.md, skills/dgf-process/SKILL.md, skills/dgf-audit/SKILL.md, .ai-factory/DESCRIPTION.md, .ai-factory/plans/feature-dgf-specific-skills.md, .ai-factory/patches/2026-09-27-21.40.md, tests/test_model.py, tests/test_validate_model.py, tests/test_audit_root.py, tests/test_report.py, tests/fixtures/known-bad/model-entity-unloadable/
**Severity:** medium

## Problem

The fourth `/aif-verify` checked the model checks against a .NET build of the three generators. It found
four wrong exit codes and a template check that disagreed with the runtime:

- **An entity the runtime cannot load was CLEAN.** `<primarykey>Nope</primarykey>` with no field `Nope`
  makes `Table.InitFields` throw a `KeyNotFoundException`, so the entity loads nowhere. `validate_model.py`
  exited `0`, and `model.py`'s comments claimed "the table load throws first, on its own reference" —
  which nothing reported.
- **The template check was a probe, not the template.** Each value was parsed alone in `<cell a="…"/>`.
  - A title decoding to `x" title="y` repeats `title` in the real cell and throws; the probe parsed it and
    the reference only warned.
  - `x" a="y` parses in the real cell; the probe saw `a` twice and blocked.
- **Two smaller mismatches.**
  - Two `<primarykey>` elements were joined into `IdName`, where XmlSerializer binds the first: a false block.
  - `uimask` positions were counted in code points, where `Field.get_uiMask` counts UTF-16 code units.
- **The audit misread its own failures.**
  - A `package.json` in a workspace — collected as a draft for a validator's own call — was demoted from exit
    `3` to exit `1`, a defect in the root.
  - A validator that raised (a dangling `settings.xml` symlink) left a traceback, exit `1`, and no report.
  - In reach mode, an unreadable vendored dialect was swallowed in `edges.json_references`, so the
    `REFERRER` line vanished and the run exited `0`.
- **Wording.** Four texts equated exit `0` with every cell checked. Four named `string.Format` where the
  grid and form interpolate. The ledger still said a generated grid "always builds".

## Root Cause

- **The check stopped at the file boundary it was asked about.** `validate_model.py` was built to check
  the references an entity makes. That the entity itself must load was not in its brief, and the one line
  that said so — a comment — described what another check was assumed to do. An assumption about a
  neighbouring check, written as a comment, is never tested.
- **A model of the runtime's input was tested, not its input.** The probe reduced "is the generated file
  well-formed?" to "is each value well-formed alone?". That holds for `&` and `<`, which break any
  context. It does not hold for `"`, whose effect depends on what surrounds it. The reduction was never
  checked against the thing it stood in for.
- **Both mismatches came from reading a binding as a string.**
  - XmlSerializer's element binding keeps the first match, but the reader joined every match.
  - `get_uiMask` indexes a .NET string, but Python indexed a `str`.
  - In each case the Python type looked equivalent and was not.
- **The audit treated "the check did not finish" like "the check found a defect".**
  - The exit-3→1 demotion was keyed on the finding code, and a draft's code looked like a defect.
  - An uncaught exception exits `1` in Python, the same code the audit uses for a root defect.
  - A swallowed exception has no exit code at all.
  - Each is a failure of the audit that reads as a result about the root.

## Solution

- **`model.read_entity`** reads a `settings.xml` as XmlSerializer binds it. Only the first `<primarykey>`
  binds, and `entity_fields` now delegates to it.
- **`model.init_fields_throws`** says, in `InitFields`' own order, why the load throws:
  - a field with no `name`, or two fields with the same name;
  - no key;
  - a key that names no field.
- **`validate_model.py`** checks a settings file's own load (`entity-load`) and blocks with the new
  `MODEL_ENTITY_UNLOADABLE`. A DTD reports `NOT RUN: entity-load`.
- **The template checks skip a table that does not load**: its own file is blocked, once. The comments
  now say that.
- **Each generator's file is built as the runtime builds it** (`_view_xml`, `_grid_xml`, `_form_xml`) and
  parsed whole. `_broken` then names the first value that breaks the file with the others neutralised, or
  says the values break it together.
- **`_mask`** indexes UTF-16 code units.
- **`audit_root.py`:**
  - it leaves draft JSON (outside every `FM/`) out of its validator run, with a `NOT RUN: drafts` line;
  - a raising validator becomes `AUDIT_CHECK_FAILED` (exit `3`), keeping the report so far, and a raise
    anywhere else is caught at the top;
  - an unknown dialect raised from the graph becomes the `SCHEMA_UNSELECTABLE` dialect finding, exit `3`;
  - `edges.json_references` no longer catches it;
  - the dead `INSTALL_CODES` is gone.
- **Knowledge, provenance and docs.**
  - `data-model.md` §1 (`InitFields`, the first `primarykey`), §2 (UTF-16 positions), §3.2 (the empty-name
    fallback) and §3.6 (interpolation, a whole-file parse, the `"` cases).
  - `reference-graph.md` §1.
  - The ledger: `XmlSerializationService.cs`, corrected ranges, a fourth re-read paragraph.
  - ADR 0023's same-day erratum.
  - `pipeline.md`, the skills' exit rows and routing, `DESCRIPTION.md` (81 cases, one of them new), and
    two follow-ups in the plan.
- **Tests:**
  - 12 regression tests failed before the fix and pass after it.
  - 3 tests kill the three mutants the last verify found surviving.
  - A new known-bad case, `model-entity-unloadable`.
  - Known-good counts are unchanged, since no sample entity trips `InitFields`.
  - The reviewer's .NET differential agrees on all 400 random entities. On its 23 fixed cases, the only
    disagreements are the DTD and invalid-UTF-8 follow-up.

## Prevention

- **Check a stand-in against what it stands in for, once, with a real build when one is available.** A
  probe, a reduced parser or a reimplemented selection rule is a hypothesis about the runtime. Here a .NET
  harness of the three generators settled in minutes what three review rounds argued about.
- **Never let a comment assert what another check covers.** Either test it — a reference into the broken
  thing, asserted end to end — or say it is not covered.
- **Map every binding to its source type's semantics, not to the nearest Python type.** Which match an
  XML binding keeps, and what a string index counts, differ across languages.
- **A report tool's exit codes are for results about its subject.** A check that raises, a file it
  should not have read, or a dependency it cannot use must exit `3` with what it has, never a code that
  reads as a finding. An `except` that returns an empty result is a finding silently dropped.
