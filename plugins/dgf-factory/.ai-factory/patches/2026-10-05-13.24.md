# /dgf setup offered a false auth default instead of asking which sign-in methods the estate uses

**Date:** 2026-10-05 13:24
**Files:** skills/dgf/SKILL.md, skills/dgf/references/description-template.md, docs/adr/0028-default-team-rules-revised.md, docs/adr/0005-default-team-rules.md, docs/adr/README.md, docs/blueprint.md, docs/dgf-knowledge.md
**Severity:** medium

## Problem

`/dgf` Step 3, Call 2, said "the plugin's stack defaults are: auth by JWT Bearer plus OIDC via
Azure AD and DGPass" and offered "Keep both defaults" first. That let a user record a sign-in
stack their estate does not have. The real estate (local basic now, an external eID later) had to
be typed under "Other".

## Root Cause

ADR 0005 rule 5 took the auth "fact" from the framework's `AGENTS.md` tech-stack line, a
secondary summary, and never checked it against the host code. Later, milestone 12 read the host
code into `knowledge/application-layout.md` §5: cookie always on, with `basic`, `dgpass` and
`azure` as independent switches enabled by settings sections, and **no JWT bearer**. Nobody went
back to the rule that contradicted it, so the shipped setup question kept a default the shipped
knowledge base disproves. The format of a single default was also wrong for a fact that is a set
of independent switches, where none is a valid answer too.

## Solution

Rule 5 was demoted by a superseding ADR (0028, which restates 0005 in full). `/dgf` Call 2 now
asks sign-in as a `multiSelect` question with no default (`basic`, `dgpass`, `azure`, `none`).
`none` combined with a method is asked again, and a typed answer is recorded verbatim. The test
stack stays a keep-or-override default. The DESCRIPTION template's Stack table records "Sign-in
methods" with "none — chosen at setup" as its default. `docs/dgf-knowledge.md`'s verified-facts
row was corrected to cite the host code.

## Prevention

- When a knowledge file lands, grep the shipped skills and the ADRs' "shipped facts" for claims
  on the same topic, and supersede any that it contradicts.
- Do not take a framework fact from a summary file (`AGENTS.md`, README) when the code that
  decides it can be read. Cite the code.
- A setting made of independent switches (sign-in providers, feature flags) is a multi-select
  question that allows zero. It is never a single default.
- Regression check: `grep -rn "JWT Bearer" skills knowledge scripts` must find nothing.
