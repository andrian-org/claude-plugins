# The entity reader parsed bytes, not the text the runtime reads

**Date:** 2026-09-28 12:39
**Files:** scripts/lib/model.py, scripts/validate_model.py, scripts/audit_root.py, knowledge/data-model.md, provenance/knowledge/data-model.md, docs/pipeline.md, skills/dgf-model/SKILL.md, .ai-factory/plans/feature-dgf-specific-skills.md, tests/test_model.py, tests/test_validate_model.py, tests/test_audit_root.py
**Severity:** high

## Problem

The sixth `/aif-verify` found three defects.

- **A crash in the gate.** A `settings.xml` declaring an encoding Python does not know (`bogus-enc`, `MS-ANSI`)
  made `model.read_entity` raise `LookupError`. `validate_model.py` exited `1` with a traceback. So did the verify
  gate, since the runner calls validators in-process. It happened even when the file checked was another entity that
  only extracts a view from the broken one. .NET loads such a file.
- **Wrong names from real bytes.**
  - A file declared `ISO-8859-1` was read as `é` and `è`, where the runtime reads U+FFFD for both. That gave a false
    exit `1` on `Id\xe9` against `Id\xe8`, and a missed block on two names that collapse to one.
  - A byte-order mark that disagrees with the declaration, or a UTF-32 mark, made the check report `NOT RUN`.
- **`xml:space` read untrimmed.** `xml:space=" preserve "` on the key preserved in .NET but not here, which gave
  4 false blocks and 1 missed block.
- **Tests.**
  - Ten mutants that change an exit on real files survived. Among them were `split(",")[0]`, whose Views test was
    vacuous in the same way as the fifth round's, and the `xml:space` pop and path-depth tests.
  - The audit's "report so far" tests raised before anything had run, and `rep.ran("roles")` and
    `rep.ran("reach")` were recorded before their checks ran.

## Root Cause

- **The ledger recorded the runtime's read path, and the code did not follow it.** The fifth fix wrote down that
  `File.ReadAllTextAsync` decodes the file and XmlSerializer reads the text through a `StringReader`. `read_entity`
  still handed expat the raw bytes, so expat obeyed the file's own encoding declaration, which the runtime never
  reads. Every encoding defect follows from that one step. The fifth fix's NUL-dropping in `_blank` treated a
  symptom of the same mismatch.
- **The trim was known in one place and missed in the other.** `_check_space` trimmed `xml:space` for
  `XmlDocument.LoadXml`; `read_entity` compared it raw. Both .NET readers trim with the same `XmlConvert.TrimString`,
  but the rule was coded twice, not once.
- **The fifth round's generators never varied the encoding declaration or pad `xml:space` on the key**, so the
  differential agreed on every case it tried.
- **The survivors were pinned by fixtures an earlier branch decided.** The comma test's key named no field unsplit,
  so the init guard returned before the split mattered. The audit test raised at `graph.build`, where the report so
  far is empty either way.

## Solution

- **`model._runtime_text` decodes as `File.ReadAllTextAsync` does.**
  - It uses the byte-order mark, UTF-32 LE's before UTF-16 LE's as the `StreamReader` tries them, else UTF-8, with
    `errors="replace"` for U+FFFD.
  - `read_entity` parses that text re-encoded as UTF-8, with `ParserCreate(encoding="UTF-8")` so that the
    declaration is overridden.
  - A NUL in the text is refused. It is no XML character, and expat would otherwise read a leading `<` NUL as UTF-16.
  - `_blank`'s window is now three bytes of UTF-8, and the NUL-dropping is gone.
  - The `read` trace names the encoding and the count of U+FFFD.
- **`model._space`** trims `xml:space` once, for both `read_entity` and `_check_space`.
- **`check_entity_load`**'s second `NOT RUN` reason now says what `read_entity` can still refuse: text that does
  not parse once decoded.
- **`audit_root`** records `roles` and `reach` as run only after they have run.
- **Docs.**
  - `data-model.md` §1 gains "the file is read as text first", and the trim.
  - §3.6 says that `LoadXml` does not check characters, so `&#0;` and lone surrogates fail at `Save` or the load
    after it, while a surrogate pair and a prefix bound to the XML namespace load.
  - `_parse_error`'s docstring says the same.
  - The ledger gains a sixth re-read, citing `CreateFromTemplateAsync` → `SaveXml` → `LoadAsync` in all three
    managers.
- **Follow-ups.** Four were added or widened in the plan:
  - `xsi:nil`;
  - the shared lxml parse, whose encoding and namespace refusals affect every validator;
  - `_parse_error`'s two remaining false blocks;
  - XML 1.1 and BOM-less UTF-16.

  The DTD item now names only the DTD.
- **Tests.**
  - 8 regression tests failed before the fix, 3 of them on the crash, and pass after it.
  - Every expected value was read first from a .NET build through `File.ReadAllText` + `StringReader`. The
    tables, run exactly as the tests write them, agree on all 45 rows.
  - A `validate_model.py` test pins both Latin-1 cases end to end: the pair `Id\xe9` and `Id\xe8` exits `0`, and the
    twins exit `1`. The old byte reading fails it.
  - 28 mutants — the reviewer's survivors adapted, plus one per new rule — are all killed. The DTD refusal is killed
    without lxml.
  - The reviewer's differential now agrees on 6,193 of 6,193 fixed entities and 6,000 random ones. The encoding
    set's crashes, false and missed blocks, and differing keys all went to zero; what remains is the follow-ups.
  - Known-good counts are unchanged.

## Prevention

- **When a ledger records a read path, make the code take that path.** Here: the same decoder, the same reader, the
  same input. A stand-in that starts from a different input — bytes where the runtime has text — differs on every
  axis that input carries, and no fix downstream of it is complete.
- **Code a runtime rule once.** Two readers that apply one .NET rule (`xml:space` trimming) call one helper.
- **Give each regression fixture a single deciding branch.** Before trusting a test, name the branch that decides
  it; if an earlier guard decides first, the test pins that guard, not the rule in its name.
- **For a "report so far" test, raise after something has run,** and assert what ran as well as the lines.
