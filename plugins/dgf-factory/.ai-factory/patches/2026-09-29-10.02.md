# A refused baseline crashed the script instead of exiting 3

**Date:** 2026-09-29 10:02
**Files:** scripts/lib/baseline.py, tests/test_baseline.py
**Severity:** low

## Problem

The ninth `/aif-verify` fed `baseline.load()` a saved baseline whose row held a `code` that is a list or an object.
`code not in report.CODES` hashes the value, so it raised `TypeError: unhashable type` and the script exited `1` with
a traceback. Exit `1` is a blocked change, which the writing skills answer with a `CHANGE_*` STOP. ADR 0025 §4 says a
baseline that cannot be used is `BASELINE_UNUSABLE`, exit `3`.

## Root Cause

The row check tested membership before it tested the type. The refused cases in `test_baseline.py` tried only an
unknown string code, so the one path where the lookup itself can fail was never run.

## Solution

`load()` requires `isinstance(code, str)` before the lookup. Two refused cases were added, run first and seen to fail
with the `TypeError`: a code that is no string, and a row that is no object.

## Prevention

- **Validate the type of a value before using it as a dictionary key.** A membership test on parsed JSON can raise
  on a list or an object.
- **A refusal test should offer each field every JSON type**, not only a wrong string.
