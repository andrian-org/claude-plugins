# Dependency-absence tests defeated by the venv re-exec; Ctrl+D at a CLI prompt crashed

**Date:** 2026-10-26 20:13
**Files:** tests/helpers.py, cli/prompt.mjs, cli/commands/setup.mjs, cli/commands/uninstall.mjs, tests/cli/setup.test.mjs, tests/cli/uninstall.test.mjs
**Severity:** medium

## Problem

1. Under plain `python3`, with a contributor `.venv/` at the source root, six tests that prove a script
   runs without lxml and jsonschema failed (`test_audit_root.Dependencies`, `test_check_change.Usage`,
   `test_inventory_root.Inventory`, `test_validate_model.Dependencies`, `test_verify_gate.Discovery`,
   `test_verify_gate.WithoutDependencies`): exit 0 or 2 where 3 was expected. `tools/check-dual-schema-docs.sh`
   passed, because it runs the suite with `.venv/bin/python` itself.
2. Ctrl+D at `dgf-factory setup`'s harness prompt printed `ERROR [main.entry] unexpected failure
   error=AbortError: Aborted with Ctrl+D` and a Node stack trace.

## Root Cause

1. `tests/helpers.py` `run_cli_blocking` makes the modules unimportable by setting `sys.modules[name] = None`
   in the interpreter it starts. Since ADR 0031 every entry script's first line is
   `runtime.use_project_venv()`, which re-executes into `<root>/.venv` when that interpreter is not the
   running one. The re-exec starts a fresh process where the blocking does not exist, so the dependencies
   imported after all. The helper predates the re-exec and was never told about it; the suite only stayed
   green because the docs check happens to run it from inside the venv, where no re-exec occurs.
2. `readline/promises` rejects `question()` with an `AbortError` on Ctrl+D or Ctrl+C. Every prompt called
   `io.question()` directly, so the rejection reached `entry()`, which treats anything that is not a
   `CliError` as an unexpected failure.

## Solution

1. `run_cli_blocking` sets `DGF_NO_VENV=1`, the documented switch that disables the re-exec, so the script
   stays in the interpreter whose imports are blocked.
2. New `cli/prompt.mjs` `ask(io, question)` turns an `AbortError` into `CliError(3, 'cancelled at the prompt —
   nothing was changed')`. Every prompt in `setup` (harnesses, apply, recreate, remove) and `uninstall`
   (remove) goes through it. All prompts come before any write, so the message is true.

## Prevention

- A test helper that changes the interpreter's environment (blocked modules, patched `sys.path`) must also
  set `DGF_NO_VENV=1`, or the script under test leaves that interpreter.
- Run the Python suite under plain `python3` as well as under `.venv/bin/python` before a commit that
  touches `scripts/lib/runtime.py` or an entry script's first lines.
- Never call `io.question()` directly in `cli/`; use `ask()`. A test that feeds an aborting terminal
  (`tests/cli/setup.test.mjs`, `uninstall.test.mjs`) covers each command that prompts.
