# Setup's line prompt installed the newest pack for an estate older than every pack; known-good checked deps before --pack

**Date:** 2026-11-04 23:26
**Files:** cli/commands/setup.mjs, cli/preview.mjs, tools/run_known_good.py, tests/cli/lines.test.mjs, tests/test_run_known_good.py
**Severity:** medium

## Problem

Two defects found by `/aif-verify` on `feature/dgf-version-packs`:

1. With `dgf.version: "0.9.0"` (older than every knowledge pack), interactive `dgf-factory setup` printed the
   refusal as a note, offered no default ("Number or line:"), and on Enter installed the newest line, 1.3, with the
   wrong note "the estate declares no DGF version". ADR 0036 §3 says that case is refused unless `--dgf-line` is
   given. A line typed at the prompt was also labelled "from --dgf-line".
2. `tests/test_run_known_good.py::test_an_unregistered_pack_is_exit_3` failed under an interpreter without lxml and
   jsonschema (RULES.md): it got `DEPENDENCY_MISSING` instead of "no knowledge pack for DGF line 9.9".

## Root Cause

1. `chooseLine` caught the `EXIT_BLOCKED` refusal and kept only its message (`{ line: null, note }`). `askLine`
   then re-selected with `selectLine({ flagLine: '' })` for an empty answer. An empty string is falsy and the call
   carried no `configVersion`, so the rules fell through to "otherwise the current line". The refusal was turned
   into data, and the second selection call ran without the inputs that produced it.
2. `main()` called `deps.require()` before `resolve_pack()`, though resolving the pack needs only the stdlib
   `tools/packs.py`. The test passed in the suite only because the machine's Python has lxml installed.

## Solution

1. `chooseLine` keeps the refusal itself (`fallback.refusal = err`). `askLine` returns the fallback on Enter when
   there is a default, and otherwise throws the original refusal: exit 1, the same message as the non-interactive
   path. A typed answer gets `source: 'prompt'`, rendered "from your answer at the prompt". The `[FIX]` traces
   print only under `DEBUG` / `LOG_LEVEL`.
2. `resolve_pack()` now runs before `deps.require()`. The test runs through `helpers.run_cli_blocking`, so lxml
   and jsonschema are unimportable in every suite run, not only on a machine without them.

Regression checks: node test "on a terminal a version below every pack offers no default …" and
`tests.test_run_known_good.Arguments`. Both failed before the fix and pass after. npm test 110/110; contract check
CLEAN with 1476 tests; the no-dependency run of the changed modules, 244 tests OK; `run_known_good --pack 1.3` CLEAN.

## Prevention

- When a refusal is caught to offer an interactive choice, keep the error object and re-throw it when the user
  makes no explicit choice. Never re-run the selector with fewer inputs than the call that refused.
- A prompt that shows no `[Enter keeps …]` hint must not accept an empty answer.
- Validate arguments (exit 3) before checking dependencies; a usage error must not depend on the environment.
- A test asserting a specific finding or message from a script that imports lxml/jsonschema should use
  `helpers.run_cli_blocking`, not `run_cli`, so the RULES.md "without lxml and jsonschema" rule is checked in every
  run.
- Every row of a plan's selection table that says "node test" needs one, including the interactive rows.
