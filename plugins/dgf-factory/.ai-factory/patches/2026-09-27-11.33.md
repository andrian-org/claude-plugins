# A generated template was trusted to build, and the audit mistook the root's defects for its own call

**Date:** 2026-09-27 11:33
**Files:** scripts/lib/model.py, scripts/lib/graph.py, scripts/audit_root.py, knowledge/data-model.md, knowledge/reference-graph.md, provenance/knowledge/data-model.md, tools/known-good-exceptions.txt, skills/dgf-component/SKILL.md, skills/dgf-process/SKILL.md, skills/dgf-model/SKILL.md, docs/adr/0023-dgf-specific-skills.md, docs/adr/0024-learning-loop-revised.md, docs/pipeline.md, docs/architecture.md, docs/dgf-knowledge.md, tests/test_model.py, tests/test_validate_model.py, tests/test_graph.py, tests/test_audit_root.py, tests/fixtures/known-bad/model-view-template-throws/
**Severity:** medium

## Problem

The second `/aif-verify` on the DGF-specific-skills branch found two blockers and a set of warnings:

- **A missing view the runtime throws on only warned.** zims `CarModelHasCategory/settings.xml:15`
  names its own `default` view, which does not exist. `validate_model.py` reported
  `MODEL_REFERENCE_TEMPLATED` (exit `2`), and `knowledge/data-model.md` §3.2 said "no error is raised".
  But the entity's only `Text` field is its key, so `LookUpViewManager.GetXmlTemplate` dereferences
  null. The same gap exists for a form generated when there is no `default` form and some field has no
  `uimask`: `FormManager.GetXmlTemplate` throws there.
- **Reach on a lookup dialog exited `3`.** `audit_root.py --reach a/FM/_LOOKUP/People/_dialog.xml`
  failed with `AUDIT_REACH_NOT_ARTIFACT`. `graph.artifact_of` named `multitask` itself but not
  `lookup-dialog`, which DD8 requires.
- **One malformed JSON file made the whole-root audit exit `3`.** The audit copies validator `ERROR`
  lines with their own severity, so `FAMILY_UNRESOLVED` (a validator's usage code) became the audit's
  exit code. `/dgf-audit` then stopped with "the call is wrong".
- **Unresolved `template` references no validator checks were dropped.** `REPORTED_ABSENT` kept only
  `throws` and `caught`, so 13 `invoke-form` references to missing forms in the samples were reported
  by nothing.
- **Smaller issues:**
  - Script calls in `/dgf-component`, `/dgf-process` and `/dgf-model` had no Exit/Action table.
  - ADR 0023 miscounted two sample figures, and ADR 0024 miscounted the fixtures.
  - Three docs were stale.

## Root Cause

- **The template branch was read as "the file gets written", never as code that can fail.** The first
  fix round added four inputs to read each loader for: present, missing, empty, and folder present
  without its file. All four stop at the loader's own branch. None of them opens the function that
  branch calls. `CreateFromTemplateAsync` calls `GetXmlTemplate`, a second function with its own
  preconditions: a `Text` field that is not the key for a view, and a `uimask` on every field for a
  form. It sits one call deeper than the knowledge was read.
- **An artifact list was completed in the design and half done in the code.** DD8 named two artifacts
  that `plan.artifact()` lacks. The code covered the one its own tests needed (`multitask`, found by root
  tag), and the other was left, because no test built a dialog as a reach target.
- **A severity copied is a meaning copied.** A validator's exit `3` means "you called me wrongly".
  Carried unchanged into the audit's report, it meant "you called the audit wrongly", which was false.
- **`When absent` values were filtered in code, not by the table.** The audit's list of which values to
  report was written for the loaders that throw. `template` was left out without anyone deciding to
  leave it out, although the audit promises every unresolved reference no validator checks.

## Solution

- **`model.py` reads the target table's key and fields** with expat (stdlib, and a DTD is refused), in
  `entity_fields()`.
  - `_view_template_throws`: a missing view whose table has no `type="Text"` field besides its first
    key is `Unresolved(throws=True)`.
  - `_form_template_throws`: a missing form with no `default` to copy, and a field with no `uimask`, is
    `Unresolved(throws=True)`.
  - The existing `throws` flag carries both through `validate_model.py`, which reports them as
    `MODEL_REFERENCE_UNRESOLVED`, and through `graph.py`, where `when_absent` becomes `throws`.
    Grids are left alone: their template falls back to the key and always builds.
- **`graph.artifact_of`** names `<ws>/FM/_LOOKUP/<dialog…>/_dialog.xml` as `lookup-dialog`, matching
  every segment exactly.
- **`audit_root.py`:**
  - `in_the_root()` copies a validator's exit-`3` `ERROR` at exit `1`, except `DEPENDENCY_MISSING` and
    `KNOWLEDGE_TABLE`, which are about the install.
  - `REPORTED_ABSENT` gains `template`, worded as the runtime writing a default into the workspace.
- **Knowledge:**
  - `data-model.md` §3.2, §3.4, §3.6 and §4 state what the templates need. 18 of the samples' 429
    entities have no `Text` field besides their key, and every sample field carries a `uimask`.
  - `reference-graph.md` §1 lists all three workspace-state exceptions to `template`.
  - The ledger records the lines read.
- **Known-good:** one new `EXCEPTION`, for `CarModelHasCategory`, citing `LookUpViewManager.cs`. The
  baseline moves to 100 excused, and `TEMPLATED` from 11 to 10. The verdict is CLEAN.
- **Skills, ADRs and docs:**
  - Every script call in the three writing skills has an Exit/Action table, and the reach rows handle a
    plain usage error.
  - `/dgf-model` STOPs on a new error in another entity.
  - Dated errata in ADR 0023 (the counts, and the generated-template fact) and ADR 0024 (six fixtures).
  - The stale lines in `pipeline.md`, `architecture.md` and `dgf-knowledge.md` are corrected.
- **Tests:**
  - 9 regression tests failed before the fix and pass after it.
  - One new known-bad case, `model-view-template-throws`.
  - Coverage the verify found missing, added after the fix: a `SubWorkflow` called from a process-local
    workflow, with a decoy at the prefixed path (a prefixing mutant fails it); each route to an entity
    in a root where it is the only one, `invoke-form` → `form-table` included, by switching
    `invoke-table`'s `Reach` off; and `AUDIT_REFERENCE_DYNAMIC` end to end. They replace a test that
    accepted any of three edge kinds.
  - Two existing fixtures were corrected to match the runtime: `test_model.py`'s `SETTINGS` gains a key
    and `uimask`s, and the `TEMPLATED` warning test gives `Status` a `Text` field. Each had tested a
    case the runtime would have thrown on.

## Prevention

- **When a loader falls back to generating a file, read the generator too.** Its preconditions are the
  reference's preconditions. Look for `FirstOrDefault(…).X`, `[0]` and `throw` inside `GetXmlTemplate`,
  `Copy` and any `CreateFrom…` method.
- **A test fixture must be a file the runtime would load.** A settings fixture with no `primarykey` or
  no `uimask` makes every test built on it prove a case the runtime throws on. Build fixtures from the
  knowledge file's own rules.
- **When a design lists N special cases, test each of the N.** DD8 named `lookup-dialog` and
  `multitask`; one test per named artifact would have caught the gap.
- **Map a severity when crossing a tool boundary.** A finding that a callee reports about its own call
  becomes a finding about the data when the caller's call was valid. Decide the mapping once, in one
  function, and test it with a callee's usage code.
- **When code filters on a knowledge column's values, the filter covers every legal value, or says why
  one is left out.** Check each value (`throws`, `template`, `caught`, `skipped`, `unknown`) against the
  promise the report makes.
