## 3. Membership deltas — what this set knows that the live MCP does not say

**11 files are present but not indexed by the MCP.** `SchemaIndexService`
(`src/Tools/dgf-mcp/Services/SchemaIndexService.cs`) globs `*Configuration.schema.json` and adds
exactly one allow-listed file, `StandaloneJsonSchemas = ["componentValidator.schema.json"]`.
Everything else in `Schemas/Json/` is a `$ref`-only sub-schema, excluded so it does not surface
as a bogus component type. They are vendored anyway: a validator that resolves `$ref` needs
them.

- `ApiDataSource.schema.json`
- `CodeDataSource.schema.json`
- `DocumentDataSource.schema.json`
- `IDataSource.schema.json`
- `InputGroupConfig.schema.json`
- `NumberConfiguration`
- `RawSqlDataSource.schema.json`
- `RowConfig.schema.json`
- `SectionConfig.schema.json`
- `StaticOptionsDataSource.schema.json`
- `TableDataSource.schema.json`

**One file is vendored twice, on purpose.** DGF's own `sync-schemas.sh` copies the hand-authored
`docs/schemas/componentValidator.schema.json` *into* `Schemas/Json/`, which is why it is the
lone draft-07 among the generated set. `json/componentValidator.schema.json` and
`standalone/componentValidator.schema.json` are byte-identical. Both are kept: `json/` must
remain a faithful mirror of `Schemas/Json/` or the drift check cannot diff it.

**Only 1 of the 3 standalone contracts is synced upstream.** `dataFetcherConfiguration` and
`eventBase` exist in `docs/schemas/` alone and are served by no MCP tool.

**Case-collision pair.** `standalone/dataFetcherConfiguration.schema.json` (draft-07, 5.6 KB)
and `json/DataFetcherConfiguration.schema.json` (draft-04, 53 KB) differ only in the case of
the first letter. On a case-insensitive filesystem, one directory would silently hold one
file. The directory split is the mitigation; **never flatten them.**

## 5. Re-vendoring

Mirrors DGF's own flow; see `docs/dgf-schemas.md` §10. In the DGF repository:

```bash
dotnet run --project src/Tools/SchemaExporter
bash src/Tools/dgf-mcp/sync-schemas.sh
```

Then, here — as a **deliberate act**, never on a schedule:

1. Confirm the upstream flow above is current, or run it.
2. Copy the three sets into `json/`, `xsd/` and `standalone/`, respecting §3's directory split.
   Quote every path: one filename contains a backtick.
3. Regenerate this manifest — new commit SHA, date, digests, and any dialect or membership
   change. Do not hand-edit the digest list. The regenerator ships alongside the drift check;
   until it does, this file is produced by a script held outside the repository, and any
   regeneration must reproduce the committed file byte-for-byte from the vendored set.
4. Re-read `docs/wiki/AI-Authoring/format-coverage.md` and update any parity claim under
   `knowledge/` that repeats it.

DGF's `/dgf-freshness-audit` catches a forgotten upstream sync and blocks the release.
**That audit does not see this plugin.** A vendored set that changes without a recorded
decision is worse than one that is knowingly old.
